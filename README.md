## 这一批（B3）交付了什么

核心是一句话：**例句真的是按他的兴趣写的，而且这句话是一整条真实的 AI 链路产出的。**

| 路由 | 做什么 |
|---|---|
| `/study/[sessionId]` | 学习页。两种卡片模板（`recognize` 看英选中 / `recall_spell` 中译英）+ 三级反馈 + 兴趣域例句 + 页内终态 |

B3 新增的关键设计（都不是随手写的，每条都有代价在后面）：

| 设计 | 一句话 |
|---|---|
| **`lib/plan/todayPlan.ts`** | 装配口径的**唯一实现**（`validateScope → resolveScope → mergeProfile → chooseMode → dailyCapFor → buildDailyPlan` 六步收成一个纯函数）。首页 / 结果页 / 学习页共用它 —— 这是"结果页说 36 个、首页显示 20 个"那类 bug 的根治 |
| **`lib/ai/config.ts`** | **全项目唯一允许出现模型名的地方**。缺 Key 的一档**直接跳过而不抛错**，所以本机没配 Key 也能跑通全流程 |
| **缓存分层提示词** | 不变的部分（角色 + JSON schema + 固定约束）放 system 且**逐字稳定**，变化的部分（兴趣域 + 单词）放 user。命中缓存后输入价是未命中的 **1/30** |
| **Ground truth 注入** | 词头 / 音标 / 词性 / 义项由**服务端从种子数据查**，请求体只传 `wordId`。模型碰不到"事实"，只能编"句子" |
| **降级链** | 一律 `DeepSeek → GLM → 模板句`（2026-09-25 定案）。曾把例句这类轻活排成"GLM 免费档打头"想省钱，当天就被线上实测推翻 —— 免费档**并发只有 1**，工作日白天几乎必挂，省下的钱换成了"每次请求先白等一轮失败"。谁排前面只在 `lib/ai/config.ts` 的档位表里写一份，业务代码不做判断。模板句是确定性代码，所以**永远不会失败** |
| **退避重试 + 冷却** | 重试前先等（默认 1.2 秒）—— 免费档并发 1，超时后立刻重发会撞上还在跑的上一次，这正是"兜底档每次都失败"的病根；撞限流就换下一档；余额不足/密钥错这类死症打 5 分钟冷却，之后连试都不试 |
| **答完才取例句** | 不在卡片出现时预取。预取等于"用户还没答就先花一次钱"，而且翻页跳过就白花了 |
| **`cached_tokens` 单独记账** | `input_tokens` / `output_tokens` / `cached_tokens` 分开记；另有 `priced` 区分"0 元"与"**没价**"（后者绝不能静默当成免费）、`peak` 标记高峰时段（DeepSeek 高峰 = 空闲 × 2） |

## 本地假模型：没有 Key 也能验通 AI 链路（`scripts/mock-ai-server.mjs`）

真 Key 要实名、要充钱，验收会真的花钱。但**最容易被写错的地方跟模型的智力完全无关**：
请求体拼得对不对、system 提示词是否逐字稳定、返回的 JSON 外面套了一层代码块围栏时代码崩不崩、
token 记账拆得对不对。这个 40 行的假模型把这些链路**原样**走一遍。

```bash
# 终端 A
node scripts/mock-ai-server.mjs
# 终端 B
npm run dev
```
然后把 `.env.local` 里的 `AI_BASE_DEEPSEEK` / `AI_BASE_GLM` 都指向 `http://127.0.0.1:8787`
（`.env.example` 底部有一段可直接抄的配置；模型名不用写，有代码默认值）。

> **它会打印每一通请求的 system 提示词指纹。** 指纹在两次调用之间变了，
> 就说明提示词里混进了"每次都不同"的东西（时间戳、随机 id、顺序不稳定的字段），
> 线上缓存命中率会变成 0 —— 而**这个 bug 不报任何错，只会让账单变贵**。
> 实测两次不同兴趣的请求指纹相同（`38f76819fee8`），缓存分层设计成立。

换档验降级链：`MOCK_MODE=500`（退避重试 + 降级）/ `429`（撞限流该痛快换档）/ `402`（死症该打冷却）/ `garbage`（schema 失败）/ `slow`（超时）/ `empty`（token 取不到记 0）。

想同时模拟"这一家坏、那一家好"，**再起一个实例换个端口**即可：

```bash
# 终端 C：专门扮演"坏的那家"
MOCK_PORT=8790 MOCK_MODE=429 node scripts/mock-ai-server.mjs
# 终端 D：让 DeepSeek 指向它（首选档变"坏"），GLM 仍然指向 8787（好的那家）
AI_BASE_DEEPSEEK=http://127.0.0.1:8790 npm start
```
（这样"首选档限流 → 换下一档"整条链能在本机真实走一遍，不必改文件。）

> ⚠️ 假模型的句子句式是固定的，所以它证明的是**"兴趣真的进了提示词并影响输出"**，
> **不是**"例句写得漂亮"。真实质量要等填了真 Key 才知道 —— 这一点别蒙自己。

## 这一批（B2）交付了什么

冷启动引导三步：**问答 → 20 词自测 → 结果页**。核心是让用户答完问题后，
看到一份"像给我排的"计划 —— 而且**每一条数字都能追到出处**。

| 路由 | 做什么 |
|---|---|
| `/onboarding` | 三题问答：目标 + 期限 / 每天时长 / 兴趣（多选 ≤3）。单选点击即进，无"下一步"按钮 |
| `/onboarding/test` | 20 词四选一，跨单元轮转抽题，**全程不显示对错** |
| `/onboarding/result` | 计划摘要 + 自测档位 + 方法摘要 + 4 条"为你改了什么" + 诚实标注 + 反馈入口 |
| `/` | 未完成引导自动跳 `/onboarding`；已完成则显示今日任务单 |

B2 新增的 6 个纯函数（全部有单测）：

| 函数 | 作用 |
|---|---|
| `buildQuiz` | 抽题：跨单元轮转 + 固定种子 PRNG（**同种子必得同卷**） |
| `scoreQuiz` / `scoreAnswers` / `bandFor` | 判分与三档（入门 / 中等 / 熟练） |
| `deadlineOptions` / `daysUntil` / `describeRemaining` | 期限选项与"还剩多久"（**要说"大概"，不说精确天数**） |
| `daysToCover` | 词数摊到每天 → 预计几天过一遍 |
| `dailyCapFor` | **分钟 → 每日词数**。结果页与首页共用它，两处数字永远一致 |
| `findGoal` / `isGoalSupported` | **目标是否已收录**的唯一判定出口（首页 / 问答页 / 结果页共用） |

**这两条是实施/收尾时顺手补的，值得留档**：

> **`dailyCapFor`** —— 原先 `daily_minutes` 根本没参与到排计划里，每日词量走的是写死的
> `daily_cap`。结果页会说"每天 36 个词"、首页却说 20 个，两处打架。补上唯一来源后，
> 两个页面永远一致。
>
> **`findGoal` / `isGoalSupported`** —— 原先首页、问答页、结果页各自写了一遍
> `GOAL_OPTIONS.find(o => o.code === goal)?.supported`，**三处真值来源，改一处必漏两处**。
> 收敛到 `questions.ts` 一处，并配单测把「阶段 0 只收录中考」这条产品约定钉死：
> 谁改了 `supported`，测试立刻变红。

## 小词 —— 角落里的那颗银球（2026-09-19 新增，首版叫「控制台」）

全站常驻的一枚**深墨底 + 银字**的「词」标，**跟 App 图标是同一套打光**。参考 Next.js
开发者指示器的形态：**安静地待在角落，点开是一块面板**。它解决的是"系统在悄悄干活、
用户看不见"的问题。

**2026-09-30 补一条，它改变了这颗球的定位：它不是"一颗球 + 一个岛"两个东西，
而是同一块材料被拉长。** 球和岛**没有主次** —— 日常绝大多数时间它是一颗
**44×44 的正圆球**（日常待命）；今天还有词没背、进度在跳的时候，它**在角落里原地抻长**
成一条 **240×44 的岛**；只有"必须让你知道"的消息才配**登台**（滑到屏幕顶部，
拉成近满屏的横幅）。三个形状读起来是同一件东西的三个长度，不是三个部件。

### 四档形态

| 档 | 尺寸 | 什么时候出现 | 家在哪儿 |
|---|---|---|---|
| `dot` | 看得见 16 · 热区 44 | 收起了 / 不该露面 | 角落 |
| `ball` | **44 × 44 正圆** | 日常待命。银「词」+ 表圈进度环 | 角落 |
| `island` | **240 × 44** | 有件正在跑的事（今日进度在跳） | 角落，**原地抻长** |
| `banner` | ≤ 420 × 44 | 它要说话了（提醒） | **登台**（顶部居中） |

> 面板（`card`）不算材料 —— 它是从材料里长出来的抽屉，见 `ConsolePanel.tsx`。

> **球上那个「词」，就是 App 图标里的那一个字**（2026-09-30）。字体 / 字号 / 字重 / 银的四段 /
> 右下渐隐 —— **五项全部从 `scripts/gen-app-icon.py` 反推**，不是凭手感挑的：
> 字号 = `44 × GLYPH_RATIO(0.38) ÷ 实测墨宽比 0.930 ≈ 18px`，字重 = 脚本首个字体 `msyhbd.ttc`（微软雅黑粗体）。
> 它同时是**球与岛之间的那个共同点**：材料被拉长时银字跟着过去，所以读起来是"同一块东西变长了"，
> 而不是"换了一个深色条子"。⚠️ 那道右下渐隐（`.island-mark`）**只给球用** ——
> 岛上的字是 12px，加它只会发脏（图标脚本自己也有"小图不上细节"这条规矩）。
>
> **今天动起来了才亮。** `done === 0`（今天一个词都还没做）→ **不画环**（否则是一圈 0% 的空线，
> 不承载信息）、「词」退到 `opacity-70`；做掉第一个词 → 环长出来、「词」亮起。
> 判据是 **`done > 0`**，不是"有没有任务" —— `today` 只在首页 / 学习页写入，
> "还没排任务"这个状态一闪而过，拿它当"空着"等于这条规矩白写。

**三条不能破的规矩**

1. **厚度恒定，只有长度在变。** 除 `dot` 外所有档的厚度都是 **44**、圆角恒为 **22**，
   于是整场形变里**只有 `width` 一个属性在动** —— 正圆就是"长度恰好等于厚度"的那一档。
   ⚠️ 改造前各档厚度是 44 / 48 / 58，拉长时**又长又胖**，眼睛读到的是"变大了、换了个
   东西"，而不是"被拉开"。这条是**实测之后**立的；要动厚度，先读 `lib/island/form.ts`
   的文件头，并同步那里那条不变量单测。
2. **位置只走 `transform: translate()`。** 角落是 `bottom` 锚、台上是 `top` 锚，而 CSS 里
   `auto → 长度` **不能过渡**，硬切会"啪"地跳一帧。所以外层容器钉在视口左上角、不参与
   布局，换个位置就是 transform 在动 —— 正好落在"只动 translate / scale / opacity"
   这条产品硬约束里。详见 `lib/island/stage.ts`。
3. **只有一个光源：左上。** 底盘左上受光、右下背光，上沿与左沿各被扫到一道，字是竖直的
   缎面银 —— 跟 `scripts/gen-app-icon.py` 用的是**同一套值**（`#39372f` / `#1b1a18`）。
   径向渐变的光斑**必须写像素**（`150px 64px at 16px 13px`）：写百分比的话半径是按盒子
   尺寸算的，光斑会跟着宽度一起放大 —— 球上是一小块高光，岛上涨成一大片浅灰，
   两档立刻不像同一块材料了（实测踩过）。

**它必须分两层，这是硬约束：**

| 层 | 内容 | 谁能看见 |
|---|---|---|
| **用户层** | 今日进度环、一键继续、动态提示 | 所有人（默认） |
| **开发者层** | 本地库规模、数据置信度、在线与否、动效是否降级、清空 | **长按 0.6 秒**才出现 |

> 开发者信息**绝不能漏给普通用户**（"数据置信度 0.75"对用户毫无意义，只会显得不专业）。
> 面板回归用户视角，措辞一律用大白话。

| 位置 | 作用 |
|---|---|
| `components/console/ConsoleDock.tsx` | 小词本体 —— **承载材料的那一个 `<button>`**：材质、形变、位置、手势判定（点击 / 拖拽 / 长按）、外部点击/Esc 关闭、网络监听 |
| `components/console/ConsolePanel.tsx` | 面板：今日任务 / 继续学习 / 动态流 /（开发者模式）运行状态与工具 |
| `lib/island/form.ts` | ★ **纯逻辑**：「这一刻该长什么样」（四档 + 厚度恒定 + 动效降级），有单测 |
| `lib/island/stage.ts` | ★ **纯逻辑**：「待在角落还是登台」+ 两套坐标 + 面板封顶高度，有单测 |
| `components/console/IslandBall.tsx` | 球档的脸：银「词」（**= App 图标里的那一个字**，18px / bold / `.island-mark`） |
| `components/console/IslandStretch.tsx` | 岛档的脸：**进度环 + 「今日 3 / 24」+「还剩 21 词」**（⚠️ **没有「词」字** —— 球才是身份，岛只报数；贴右时整体镜像） |

| `lib/console/probe.ts` | 读本机状态：本地库规模 / 在线 / 动效是否降级 |
| `lib/plan/todayProgress.ts` | ★ **纯逻辑**：今日完成量（只读 `review_logs`，按本地日界过滤，有单测） |

> **质感（墨底 + 银字 + 银光）不在 TSX 里**，在 `app/globals.css` 的三个类：
> `.island-material`（墨底 + 左上打光）、`.island-silver`（竖直缎面银，四段停点）、
> `.island-mark`（**只有球用**：在银底上再加一道右下渐隐）。
> 想调质感只改这三处，组件只管"什么时候用它"。**三个坑写在 CSS 注释里，动手前先读：**
> ① 径向光斑**必须写像素**（写百分比会跟着盒子宽度一起放大，球上是一小块高光、
> 岛上涨成一大片浅灰，两档立刻不像同一块材料）；
> ② 银字裁进字形靠 `background-clip: text`，**只能加在叶子元素上** —— 加在父元素上再给子元素
> 设 `opacity`，裁切会失效（那道银会照满不透明度画出来，该淡的不淡）。
> 要"淡一点"就淡在**自己身上**（`.island-silver.opacity-70`）；
> ③ **先给不透明 `color`，再在 `@supports` 里换 `transparent`** —— 裁切一旦不生效
> （老内核 / 被构建工具裁掉），`color: transparent` 会让字**彻底看不见**，这是最坏的静默故障。

**任何地方都能推一条提示**，一行搞定，不需要 hook、不需要 Provider：

```ts
import { pushNotice } from "@/lib/console/store";

pushNotice({ key: "daily-plan", level: "info", title: "今日任务单已排好", detail: "12 个词 · 约 15 分钟" });
```

`key` 是去重键：**同 key 的新提示会顶掉旧的**，所以"每次进首页推一条"不会滚成一屏。
`level` 取 `info | success | warning | danger`，后两档会让小词亮起一圈柔光并带个小点。

### 实现上的三个坑（都实测踩过）

1. **进度环只能画在圆盘内侧。** `app/icon.png` 是**满幅圆**（圆边到画布边、四角透明），
   环画到外圈会被裁掉。所以环走内沿——正好当成金属盘的一圈表圈。
2. **位置不能靠切 CSS 锚点，得走 `transform: translate()`。**
   （2026-09-19 记的是"必须用 `bottom` 锚、不能用 `top`"——那时只有角落一个家。
   2026-09-30 加了"登台"之后这条升级了：角落天然是 `bottom` 锚、台上天然是 `top` 锚，
   两套锚点落在同一个元素上，而 CSS 里 `auto → 长度` **不能过渡**，硬切会"啪"地跳一帧。
   所以现在外层容器**钉在视口左上角、完全不参与布局**，位置全部由 `transform: translate()`
   表达 —— 换家是 transform 在变，于是可平滑过渡。见 `lib/island/stage.ts`。）
   同理还有两条**贴着哪一边就往哪一边长**的规矩：贴右时材料要**镜像**
   （`flex-row-reverse`），否则进度环会瞬间跳 200+ px（实测：贴右时 `x + w` 恒为 1234）；
   容器水平对齐必须跟着 `spot.side` 切 —— 写死 `items-start` 的话，
   球拖到右边再展开面板会**瞬间"跳"到面板左端**（实测踩过）。
3. **收起态那颗小点必须用实色品牌色 + 44px 热区。** 用 `bg-strong`(#d6cfc5) 半透明压浅底，
   实测对比度只有 1.9:1，等于**消失**（用户收起来就找不回来了）；12px 的触摸目标手指也点不中。

### 面板会在球的上下两侧换边（2026-09-19 修，重要）

面板默认排在球的**上方**。但球是可以拖的 —— 一旦球被拖进屏幕上半部，
"从球往上长"就等于把面板顶出屏幕。实测把球放到最上（顶边 16px）再点开：

```
面板顶边 −429px   而它总共才 435px 高   →   只有 6px 在屏幕里
```

两个原因叠在一起：

1. 方向写死了"永远往上"；
2. `max-h-[70vh]` 是相对**视口**算的，不是相对"球上方还剩多少"算的 ——
   它管不住"往上能长到哪"。

**修法也是两条，缺一不可：**

1. **换边。** 球在中线以下 → 面板往上长（默认落点，行为与改造前一致）；
   球在中线以上 → 面板往下长。判据是 `panelSideFor()`（`lib/console/dock.ts`，有单测）。
2. **面板高度按"那一侧真实剩余空间"封顶**，全用 CSS 表达式算：

   | 面板朝哪长 | max-height |
   |---|---|
   | 往上 | `min(70vh, 球上沿 − 缝 − 留白)` |
   | 往下 | `min(70vh, 100vh − 球下沿 − 缝 − 留白)` |

   这样面板**在任何位置都不可能伸出屏幕**，内容多了在面板内部滚动。
   而且因为表达式里全是 `vh`，**顺带省掉了 resize 监听** —— 转屏、
   手机地址栏收放全都自动跟上。

> 容器的锚定方向要跟着面板走：面板朝上 → 锚 `bottom`；面板朝下 → 锚 `top`。
> 锚错方向的话，面板一展开就会把球顶走。
>
> 为什么"中线 0.5"够准：精确分界是 `(视口高/2 − 球/2 − TOP_LIMIT) / 行程`，
> 代入 300~1400px 的视口落在 **0.500~0.509**。单测把这条近似钉死了，
> 而且就算判偏也不会出 bug —— max-height 是按那一侧真实空间算的。

实测（球拖到 6 个高度 + 3 个边界场景，越界像素全部为 0）：

| 球的位置 | 球顶边 | 面板 | 越界 |
|---|---|---|---|
| ratio 0（最上） | 16px | 下方 70–505 | 0 |
| ratio 0.49 | 390px | 下方 444–832 | 0 |
| ratio 0.50（中线） | 398px | **换成上方** 12–388 | 0 |
| ratio 1.0（最下，默认） | 780px | 上方 335–770 | 0 |

另测：右上角 + 开发者模式（面板最长 591px）→ 70–661 可滚动；
矮视口 390×480 → 70–406；横屏 844×390 → 横向 489–809、纵向 70–343。均为 0 越界。

> 面板长在下方时，入场方向也镜像了一下（`data-rise="down"` 把 `--motion-shift`
> 取负），这样它读起来是"从球里落下来"，而不是穿过球钻出来。
> 系统开了「减少动态」时 `animation: none`，位移一律不出。

## 离线与「添加到主屏」（B4 · 门房）

```
   浏览器页面 ──请求──▶ ┌──────────┐ ──放行──▶ 网络（Vercel / Supabase）
                       │  门房    │
                       │ sw.js    │ ──断网就把它存的那份递出去──▶ 页面
                       └──────────┘
                        本地留一份「壳」：页面骨架、样式、脚本、图标
```

**一句话**：给浏览器请一个门房，站在你和网络中间，把常用的那几样在本地留一份 ——
有网时照常去网上拿最新的（**不拦**），断网时把自己那份递给你，**页面还能打开、还能接着答题**。
顺带让手机能「添加到主屏」，点开像个小 App。

### 哪些东西怎么存（改之前先看这张表）

| 请求 | 策略 | 为什么 |
|---|---|---|
| 页面（导航） | **先联网拿** → 失败回缓存 → 再失败给离线兜底页 | 只要联网，用户拿到的就是刚部署那一版（"看到旧页面"的闸门③） |
| `/_next/static/**` | **命中缓存直接给，不联网** | 文件名带**内容哈希**，内容一变名字就变，永远不可能拿错 |
| 同源其他静态（图标 / manifest） | 先用缓存、后台悄悄换新的 | 这类文件没有哈希，但也不该每次都等网络 |
| `/api/*` | **放行，绝不缓存** | 缓存了 AI 应答 = 让用户看到别的东西 |
| 跨域（Supabase 等） | **放行** | 那边有自己的鉴权与新鲜度要求 |
| `/sw.js` 自己 | **放行**（永远走网络） | 否则门房会把自己卡在旧版本上，那是最难救的一种 |
| IndexedDB | **一个字都不碰** | 门房只管「文件」，不管「数据」（数据那条链是 `lib/db/local.ts` + `lib/sync/*`） |

### 相关文件

| 文件 | 作用 |
|---|---|
| `public/sw.js` | 门房本体。**手写、零依赖**（少一个会出错的变量）。⚠️ 它不进 typecheck、也不进 ESLint，靠契约测试盯 |
| `public/offline.html` | 离线兜底页。**完全自包含**（不外引任何东西）—— 全项目唯一一处硬编码颜色 |
| `app/manifest.ts` | 「添加到主屏」清单。Next 认这个文件名会自动挂 `<link rel="manifest">`，不用在 layout 里登记。图标分 `any` 与 `maskable` 两套 |
| `components/pwa/ServiceWorkerRegistrar.tsx` | 注册器。**只在正式构建注册**，等 `load` 之后，地址带 `?v=<构建号>` |

### ⚠️ 应急开关：万一线上门房出问题，怎么让所有人的缓存立刻作废

这是这一批**唯一一个"装上去就难甩掉"**的东西，所以先把逃生门写好。

**动作：把 `public/sw.js` 整个换成下面这一版，推一次。**

```js
self.addEventListener("install", () => self.skipWaiting());
self.addEventListener("activate", (event) => {
  event.waitUntil((async () => {
    await Promise.all((await caches.keys()).map((key) => caches.delete(key)));
    await self.registration.unregister();
    for (const client of await self.clients.matchAll()) client.navigate(client.url);
  })());
});
```

它做的事：清空本机所有缓存 → **注销自己** → 把当前页面刷新一次。
用户**下一次打开页面**时生效（已经开着不动的标签页要等它下次发起请求）。

修好真正的问题之后，用 git 把这个文件恢复回原样、再推一次即可 —— 登记会重新发生。
⚠️ 别用"改个缓存版本号"当应急手段：那只换了缓存的**名字**，坏掉的门房还在台上按老规矩办事。

### 一个必须说清的边界

**它不是"断网还能打开任何页面"。** 没访问过的页面，断网给的是那张离线兜底页。
**已经访问过**的页面（含你此刻正开着的那一页），断网**刷新**可以照常打开 ——
这就是这一批的验收线（阶段 1 方案 §9.4 的 C7）。

> ⚠️ **"当前这一页也要预热"是 2026-09-30 实测补上的一条**，别删。
>
> 门房在页面 `load` 之后才注册（见 `ServiceWorkerRegistrar` 的规矩③），
> 所以**第一次访问的那一页**是在门房上岗**之前**加载的 —— 它压根没经过 fetch 处理器。
> 而 `install` 当初**只补存了首页**。真机实测的结果：
> 「打开 `/login` → 断网 → 刷新」拿到的是兜底页，而验收线要的恰恰是"访问过的页面照常打开"。
>
> 修法是 `shellPages()`：首页 **+ `self.clients` 里此刻开着的那些窗口**
> （只取 pathname、**只存 200** —— 不存 200 是因为错误页一旦被粘住，
> 那个地址以后断网打开就永远是它）。
> 修后实测：缓存里页面从 `["/"]` 变成 `["/", "/login"]`，断网刷新逐项与联网时一致。

另外，「已登记 · 再打开一次即可接管」是**正常的中间态，不是坏了** ——
它说的是"门房还没接手**当前这个页面**"（接手要等下一次打开）。
不过**缓存本身在 `install` 那一刻就已经补好了**，所以那一档下断网刷新通常也已经能用。

### 怎么自查

小词 → **长按 0.6 秒**进开发者模式 → 看「离线缓存」那一行：

| 显示 | 意思 |
|---|---|
| `未启用` | 开发版本来就不装门房（`npm run dev` 下**这条是正常的**） |
| `浏览器不支持` | 老浏览器，或不是安全上下文（http 且没走 localhost） |
| `已登记 · 再打开一次即可接管` | 正常中间态 —— **再打开一次就好** |
| `已接管 · <版本号>` | 已生效。这个版本号应当等于**最新一次部署**的 commit 前 7 位 |

真机自查：打开一次 → 断网 → 刷新 → 页面应该还能出来（不是浏览器的"没有网络"页）。

> ⚠️ **别信"网页工具里的断网开关"**（2026-09-30 栽过一次）：
> 有些自动化工具（含 `agent-browser set offline on`）只把 `navigator.onLine` 改成 `false`，
> **请求照样发得出去**。于是"断网刷新还能打开"会**假绿** —— 它其实是联网拿的。
> 真正可信的做法只有一种：**把服务器杀掉**，再做刷新。判据是 `curl` 明确报"连接被拒绝"。
> 这条教训已写进 `browser-layout-verify` 技能。

### ⚠️ 三条会**静默出错**的硬约束（当时真踩出来的）

| 约束 | 为什么 |
|---|---|
| **版本号绝不能建在构建号 `BUILD_ID` 上** | 构建号是"每次部署都变"的（要给门房换缓存）。拿它当版本号，推一次"改个错别字"就弹一次公告，用户很快学会无视它，公告就死了。两者需求正好相反 ⇒ 必须另立一个**人写**的号 |

### 做法（都有过单测盯着，重建时照抄）

- 人写的版本号，`= RELEASES[0].version` **从数组头推导** ⇒
  "加了条目却忘了改版本号"这类错误在结构上就不可能发生。
- "看过哪一版"记在**本机** `localStorage`（不上云）。读不到时返回 `null`（= "没有记录"），
  **不要返回一个默认版本号** —— 否则新用户会被判成"看过某版"，在认识产品之前先收到一张公告。
- **三种"不弹"，都是故意的**：
  ① 从来没看过任何一版（第一次来 / 浏览器禁了存储）——不该在认识产品之前先读一份更新记录；
  同时把当前版**默默记成已看**，于是他遇到**下一版**时能正常收到。
  ② 看过这一版了 —— 这就是"之后不再打扰"。
  ③ 清单里没有这一版 —— 没话说就别弹一张空卡。
  且**只讲最新那一版，不补讲跳过的版本**（隔一个月再来，不会收到三条叠在一起）。
- **出口只有「知道了」和 Esc。** 点卡片外面**不关** —— 这是张纸条不是弹窗，它不挡任何东西；
  而"关掉"等于"以后不再提醒"，那是个**会丢信息**的动作，不该由一次误触的空白点击来触发。

挂在小词旁边，和面板**同一个槽位**（同宽 `min(20rem, calc(100vw - 2.5rem))`、同一个投影）；
同一种**暖砂托盘托一张白卡**；卡片头部那颗小石子就是**球缩到 20px**
（像素值必须按 `20 / 44` 从 44 档重算 —— 那套径向光斑是**像素**写的，照搬会让光源跑到右下；
且**不放「词」**：20px 上的字形只有 8px 高）。
入场复用全站唯一那条 `rise-in`（`data-animated`）—— "减少动态效果"的降级**白拿**，别写第二套动画。

> 当时的实测记录（含公告三态、手机贴左/贴右、与面板让位）：`.workbuddy/memory/2026-09-30.md` §十二。

## 界面约定（排版 / 配色 / 图标）

**排版三层**（2026-09-19 立，新页面一律沿用）：

1. **字号阶梯**：主数字 44px ＞ 正文 14px ＞ 辅助 12px ＞ 标签 11px（标签配 `tracking-[0.08em]`）

**图标**（`app/icon.png` / `app/apple-icon.png` / `app/favicon.ico`，外加两张 `public/icon-maskable-*.png`）：

> ⚠️ 这五张里有**三张是满幅的**（`apple-icon.png` 与两张 `icon-maskable-*`），
> 但**理由不是同一个**：安卓那边是"保险"，iPhone 那边是**硬性规矩**（透明像素会被填黑）。
> 分别见下文「满幅（maskable）图标」与「`apple-icon.png` 为什么也必须满幅」两节。
> 剩下两张里，`icon.png` 是**四角透明的圆片**（那是对的，别顺手也改成满幅）。

- 设计语言：**深墨圆 + 银字「词」**，参考 Next.js 默认图标那种"深底亮标"的做法，
  再往**金属浮雕**推了一步。三处细节共用**同一个光源（左上）**，所以能"立"起来：
  底盘（左上亮、右下暗 + 贴边一道细高光）／笔画（左上沿亮、右下沿暗的倒角）／
  字形（右下角渐隐化进底盘，取自 Next.js「N」的做法）。
- **字是"银"不是"白"**：竖直方向有明暗渐变（上亮下暗）。平涂的白在深底上像贴纸，
  有明暗层次才像一块金属。
- **图标是生成物，不要手改 PNG。** 改造型 / 配色改 `scripts/gen-app-icon.py` 后重跑：

**满幅（maskable）图标 —— 2026-10-01 加**

安卓会把图标塞进**它自己画的形状**里（圆形 / 方圆形 / 圆角方形），边缘直接切掉。
只给一张"内切圆片"的话，切到带角的外壳时，**四个角会是透明的**，
露出桌面底色 —— 一圈白边，而且**桌面浏览器预览一切正常，只有真机上看得见**。

所以同一个标要出**两套**，**且不许合并成一个文件**：

| | 文件 | 声明 | 长什么样 |
|---|---|---|---|
| 普通版 | `app/icon.png` | `purpose: "any"` | 深墨圆**内切**在正方形里，四角透明 |
| 满幅版 | `public/icon-maskable-192.png` · `-512.png` | `purpose: "maskable"` | 底色**铺满**整张画布，形状交给系统切 |

> ⚠️ **不要写 `purpose: "any maskable"`。** 那是"两种场合里必有一种不对"的写法：
> 只给满幅版，不认 maskable 的地方会把整块方料原样显示（字看着偏小、四周空一圈）；
> 只给普通版，安卓会把它塞进自己画的底色里（圆片外露一圈白边）。
> `lib/pwa/manifestIcons.test.ts` 里有一条断言专门盯着这个。

三条规矩（`scripts/gen-app-icon.py` 文件头也写着）：

1. **底色必须铺满**，一个透明像素都不能有 —— 脚本里有一条**自检**，
   最小 alpha 不是 255 就直接中断，不会静默出一张错图。
2. **内容必须落在直径 80% 的"安全区"圆里**。当前字宽 38% ⇒ 墨迹外框的角离圆心 27.4%，
   红线 40%，余量 12.6%。**别因为"满幅看着更大"就把字放大**：字宽到 56.6% 就正好压线，
   再大「司」会被切掉。
3. **字宽与普通版同一个 38%。** 圆形外壳下"看得见的面积"就是那个内切圆，
   两边等宽 ⇒ 看起来**是同一个标**；换的只是"圆片 → 整块料"。

产出两张的原因：**192 走旧版安装条件，512 走高清档**。两张都由生成脚本一次出，
并且已经登记进 `public/sw.js` 的 `PRECACHE` —— 它们**不被 HTML 引用**，
不主动存的话，断网状态下装到主屏的图标就是空的。

验收方式（**这条只能靠真机**）：

```bash
# 本地只能看到"四种外壳都铺满、字没压线"；真正的判据是装到安卓桌面上
"C:/Users/wangh/.workbuddy/binaries/python/envs/default/Scripts/python.exe" scripts/make-maskable-preview.py
```

→ 出 `词径记-满幅图标-预览-v1.png`（工作区根目录）：四种外壳的效果模拟 + 安全区金圈 +
"拿普通版顶替会怎样"的翻车对照。**满幅图标没法在浏览器里验收** —— 桌面看到的永远是完整方图。

**`apple-icon.png` 为什么也必须满幅 —— 2026-10-01 修**

`app/apple-icon.png` 是 iOS「添加到主屏幕」专用的那张。它原来跟 `icon.png` 一样是
**内切圆、四角透明** —— 在桌面浏览器里看**一切正常**，但真加到 iPhone 上会翻车：

| | 允许透明吗 | 不认识 maskable 时 |
|---|---|---|
| **安卓** | 允许，会自己垫一块底色 | 满幅版是"保险"，不是"必需" |
| **iPhone** | **不许** —— 先画一块圆角方形的底 → 贴图标 → **透明处一律填纯黑** | 无此概念，它只认 apple-touch-icon |

后果不是"细微差别"：深墨圆片外面裹一层纯黑方底，圆与方之间一道看得见的弧线，
一眼就是没做好的样子。**按 iOS 规则模拟，圆角方之内 17.9% 的面积会被填黑**（改后 0.0%）。

> 📎 对照图自己跑，别手画：
> `"C:/Users/wangh/.workbuddy/binaries/python/envs/default/Scripts/python.exe" scripts/make-ios-icon-check.py`
> → 工作区根目录 `词径记-iPhone图标-预览-v1.png`，左"改前"右"改后"，并当场量出百分比。
> 右格读的是**磁盘上那个真身文件**、不是现场重画的 ⇒ 它同时是一张**验收图**。

**改法**：那张走 `render(APPLE_PX, maskable=True)`。
**字宽仍然是 38%，与另外三张一字不差** —— 图标在主屏上都会被缩成同样大小的格子，
字宽同为画布的 38%，三个平台看到的字一样大。满幅版换的是"圆片 → 整块料"，**不是换设计**。

> ⚠️ **别把它改回 `render(APPLE_PX)`。** 生成脚本里那句 alpha 自检只在 `maskable=True`
> 这条路上生效；改回去就**绕过了自检，而且一路绿灯** —— 浏览器照常显示、构建照绿、
> 只有 iPhone 用户看到一块黑角。`lib/pwa/appIcons.test.ts` 有一条断言专门盯着这个
> （**已实测**：把产物换成内切圆它就会红，且报错文案里带着修法）。

**本地已经验过什么（2026-10-01，都可复现）：**

## 几条不能破的规矩（改代码前先读）

1. **AI Key 只在服务端**。前端代码、客户端组件、`NEXT_PUBLIC_*` 里永不出现任何 Key。
   `.env.local` 已在 `.gitignore` 中，**不要提交它**。
2. **禁硬编码颜色**：颜色只有一份来源 —— `app/globals.css` 的 `@theme` 块，
   组件里只用 `bg-surface` / `text-secondary` 这类语义类名。
3. **禁 emoji、禁紫粉渐变、禁 bounce**；动效只用 `translate` / `scale` / `opacity`，
   **禁 3D transform、禁 `will-change`**（微信内核会白屏）。
4. **复习调度将来由 FSRS 独占**：`pace` 配置里不许出现任何复习间隔参数。
5. **`resolveScope` / `buildDailyPlan` / `mergeProfile` 必须是纯函数**：无 AI、无 IO、可单测。
6. 数据要诚实：`confidence < 0.8` 的词表，界面上必须标注"可能不准"并给反馈入口。
7. **同一个判断只允许有一处实现**。发现两个地方写了同样的 `find` / 同样的阈值 /
   同样的映射，就抽成 `lib/` 里的具名函数并加单测 —— 三处真值来源 = 改一处必漏两处。
8. **一次只改一个文件的一处**：批量编辑同一文件时，前一处会被后一处覆盖（实测踩过）。
9. **Tailwind 类名要在产物里核对**：类名写错**不会报错，只会静默失效**，三道闸门一个都抓不到。
   改完样式要从产物 CSS 里 grep 一次。注意 CSS 里类名带反斜杠转义
   （`.text-\[11px\]`），`grep -F "text-[11px]"` 匹配不到，要用宽松子串（如 `11px`）。

   ```bash
   # ① 从 HTML 里拿本次构建真正的 CSS 文件名（带哈希，别硬编码）
   curl -s http://localhost:3000/ > /tmp/h.html
   CSS=$(grep -o '/_next/static/chunks/[^"]*app_globals[^"]*\.css' /tmp/h.html | head -1)
   # ② 逐个 grep 新用到的类名，出现次数应为 ≥1
   curl -s "http://localhost:3000$CSS" | grep -c -F "shadow-float"
   ```

   > **实测实例（2026-09-19）**：新写的 `duration-base` / `duration-fast` 计数为 **0** ——
   > Tailwind v4 只认 `duration-<数字>`，`--duration-*` 不是它的命名空间。
   > 已改成 `duration-160` / `duration-200`，并在 `globals.css` 的变量旁写了警告。
   >
   > **另一个坑**：dev 模式下产物 CSS **不压缩、规则跨多行**，
   > 所以 `grep -o '\.cls[^}]*}'` 这类"一行内吃完整条规则"的写法匹配不到
   > （`}` 在下一行）。查**整条规则**要先 `grep -n` 定位再往下读几行；
   > 只查"类名在不在"用宽松子串就够了。
   > 同一天里，`[data-animated][data-rise="down"]` 这条规则就因此被误判成"没生成"过一次。
10. **资源和图标都是"生成物"**：`seed-data.json`、`icon.png`、`favicon.ico` 都由脚本产出。
    要改就改脚本重跑，直接编辑产物会在下次重跑时被覆盖。
11. **读浏览器侧的外部状态用 `useSyncExternalStore`，不要 `useState + useEffect`。**
    `localStorage` / `matchMedia` / `navigator.onLine` 这类"React 之外的状态"，
    用 effect 同步进来是 React 官方明确不建议的写法（会多一次渲染、还有撕裂风险）。
    `lib/console/prefs.ts` 就是为此重写过一版，eslint 抓过一次。
12. **浮层的位置锚 `bottom`、对齐跟着所在边切。**
    面板排在球上方 → 锚 `top` 会把球往下顶；容器写死 `items-start` →
    球拖到右边再展开会"跳"到左边。两处都实测踩过，改浮动组件前先读 `ConsoleDock.tsx` 顶部注释。
13. **浅底上的小标记要用实色品牌色，并给足 44px 热区。**
    `bg-strong`(#d6cfc5) 那种"低调的浅灰"压白底只有 1.9:1 对比度，
    实测等于**看不见**（收起后的球找不回来就是这个问题）。
    图形元素至少 3:1，触摸目标至少 44px。
14. **浮层（follow 元素走的弹窗）必须能换边，并按那一侧的剩余空间封顶。**
    写死"永远朝上"或只用 `max-h-[70vh]`，只要触发它的元素能被拖到屏幕上半部，
    弹窗就一定会有内容被顶出可视区 —— 实测教训见上文「面板会在球的上下两侧换边」。
    判据做成纯函数（`panelSideFor`）以便单测；封顶高度用 `vh` 表达式在 CSS 里算，
    这样转屏不用写 resize 监听。
15. **`.env.local` 永不入库，`.env.example` 必须入库。**
    `.gitignore` 里的 `.env*` 会把 `.env.example` 一起吞掉，所以有一行 `!.env.example` 放行它 ——
    别人克隆下来第一件事就是照着它建 `.env.local`，漏了就得多问一轮。
    另外：**不要给这些变量加 `NEXT_PUBLIC_` 前缀**，加了就会被内联进浏览器包，等于公开送 Key。
16. **装配口径只有一处实现：`lib/plan/todayPlan.ts` 的 `assembleTodayPlan`。**
    它把 `validateScope → resolveScope → mergeProfile → chooseMode → dailyCapFor → buildDailyPlan`
    六步收成一个纯函数。**任何页面都不许再写一遍这六步** ——
    "结果页说 36 个、首页显示 20 个"就是三处各写一遍的直接后果。
    同理，每日词量只走 `dailyCapFor`，今日完成量只走 `countDoneInPlan`。
17. **验 AI 链路用本地假模型（`scripts/mock-ai-server.mjs`），不要拿真 Key 去调链路。**
    真 Key 只用来验"模型写得好不好"这一件事。混在一起验的话，
    一条链路的 bug 会被误当成"模型不行"，而你会为此真的花钱。
    改完 `lib/ai/*` 之后跑一遍假模型，顺带看一眼它打印的 system 指纹有没有变 ——
    指纹变 = 缓存失效 = 账单变贵（而且它**不报错**）。
18. **`/api/ai` 必须保持动态路由。** 构建产物里它应该是 `ƒ`（按请求渲染）而不是 `○`（静态）。
    如果哪天它变成静态的，说明 Key 有可能被打进产物 —— 这是硬约束 1 在构建层面的最后一道防线，
    部署前看一眼 `npm run build` 的那张路由表。
